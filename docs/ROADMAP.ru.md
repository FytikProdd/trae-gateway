# Roadmap

## Текущее состояние

Проект уже можно использовать как:

- локальный OpenAI-совместимый gateway-каркас
- загрузчик Trae auth и заголовков
- debug/reverse proxy для приватных endpoint'ов Trae
- template-based адаптер к приватным API Trae

Чем он пока не является:

- production-grade адаптером Trae с нулевой настройкой
- полной заменой внутреннего chat/task runtime Trae

## Что блокирует `1.0`

### 1. Автоматическая генерация payload для `create_agent_task`

Текущее состояние:

- у `POST /v1/chat/completions` теперь есть режим `agent-v3-auto`, который собирает минимальный Trae-запрос без заранее сохранённого JSON template
- template-режим остаётся fallback-вариантом на случай изменения приватной upstream-схемы
- auto-builder пока сделан намеренно консервативным и ориентирован в первую очередь на обычный текстовый чат

Почему это важно:

- теперь стандартный чат можно запускать с нулевой настройкой
- но изменения протокола upstream всё ещё могут сломать builder, поэтому discovery схемы и жёсткая стабилизация всё ещё нужны

Требование для `1.0`:

- gateway должен уметь автоматически собирать корректный запрос к `/api/agent/v3/create_agent_task` из OpenAI-style input

### 2. Полный tool-call loop

Текущее состояние:

- raw passthrough для `/api/agent/v3/commit_toolcall_result` уже есть
- parser событий Trae теперь умеет поднимать OpenAI-совместимые `tool_calls`, когда в upstream-событиях есть tool metadata
- follow-up запросы OpenAI с `role: "tool"` теперь можно переводить в экспериментальный `commit_toolcall_result` payload через сохранённый session/task state
- полного OpenAI-совместимого цикла выполнения tools пока нет

Чего не хватает:

- жёстко провалидировать live-схему `agent/v3` commit payload на большем числе реальных Trae-сессий
- выполнять tools внутри gateway или окончательно стабилизировать контракт client handoff
- корректно продолжать тот же Trae task/session во всех edge cases

Требование для `1.0`:

- простой текстовый чат, streaming и tool-calling должны работать надёжно

### 3. Стабильный SSE/event parsing Trae

Текущее состояние:

- parser SSE теперь умеет разбирать multi-line frames, вытаскивать стабильные id и распознавать tool-call блоки
- извлечение текста всё ещё частично эвристическое, потому что полная upstream-схема остаётся приватной
- split между reasoning/content пока не моделируется точно

Почему это важно:

- OpenAI-совместимые клиенты ждут стабильную семантику chunk'ов
- эвристики приемлемы для debug, но не для `1.0`

Требование для `1.0`:

- парсить реальную схему событий Trae и детерминированно отображать её в streaming и non-streaming OpenAI-ответы

### 4. Жизненный цикл auth и refresh токена

Текущее состояние:

- gateway читает текущий JWT из локального профиля Trae
- перед отправкой upstream-запросов теперь есть явная проверка на протухший local auth token
- активный refresh учётных данных пока не реализован

Риски:

- протухший токен ломает gateway
- поведение зависит от того, успел ли Trae сам заранее обновить токен

Требование для `1.0`:

- либо автоматически обновлять токен, либо детектировать истечение и восстанавливаться предсказуемо
- при невозможности восстановления возвращать понятные auth-ошибки

### 5. Стабильное сопоставление сессий

Текущее состояние:

- mapping сессий теперь сохраняется локально для повторяемых external conversation ids
- переиспользование `session_id` теперь стабильно, если клиент передаёт повторяемый ключ разговора
- полное переиспользование follow-up state для всех Trae-side ids всё ещё не завершено

Чего не хватает:

- persistence для chat sessions
- детерминированного сопоставления внешнего чата с Trae `session_id`
- корректного переиспользования `task_id` / `message_id` / follow-up state

Требование для `1.0`:

- один внешний диалог должен надёжно продолжать ту же Trae-сессию

### 6. Обработка ошибок и протокольное ужесточение

Текущее состояние:

- upstream-ошибки теперь раскладываются на явные auth, rate limit, timeout, server и invalid request классы
- обработка request timeout теперь встроена в client
- routing endpoint'ов теперь умеет fallback по нескольким Trae boot domains из установленного product config

Чего не хватает:

- явной обработки `401`, `403`, `429`, `5xx`
- обработки timeout
- диагностики malformed template
- диагностики malformed upstream payload
- безопасной retry-стратегии там, где это допустимо

Требование для `1.0`:

- сбои должны классифицироваться и возвращаться консистентно

### 7. Реальный discovery моделей и возможностей

Текущее состояние:

- `GET /v1/models` теперь строится по недавно замеченным моделям из локальных Trae логов
- hints о tool capabilities теперь можно выводить из недавней Trae tool-call активности

Чего не хватает:

- обнаруживать реально доступные модели Trae
- описывать возможности вроде tool use, multimodal support и reasoning support

Требование для `1.0`:

- список моделей должен отражать реальность, а не плейсхолдеры

### 8. Тесты

Текущее состояние:

- автоматизированные тесты теперь покрывают payload generation, SSE parsing, session persistence и log-based model discovery

Минимальное покрытие для `1.0`:

- загрузка auth из Trae storage
- загрузка product/domain
- загрузка `.env`
- template rendering
- SSE parsing
- OpenAI streaming adapter
- non-streaming adapter
- upstream error mapping

## Предлагаемые milestones

## `0.2`

- сохранить стабильность текущих debug endpoints
- улучшить логирование запросов/ответов с редактированием секретов
- точнее задокументировать workflow захвата template
- добавить smoke-тесты на запуск сервера и загрузку auth

## `0.5`

- собрать надёжный parser для Trae SSE events
- улучшить persistence сессий и mapping разговоров
- добавить обработку upstream-ошибок и retry-правила
- поддержать один практический end-to-end путь:
  простой текстовый чат без ручной отладки при обычном использовании

## `1.0`

- для стандартного чата больше не нужен ручной payload template
- `chat/completions` стабильно совместим с OpenAI
- tool-call loop работает
- жизненный цикл токена обрабатывается корректно
- критические пути покрыты автоматизированными тестами
- есть документация для интеграции с Codex / Claude Code / OpenCode

## Definition of done для `1.0`

Gateway можно считать `1.0`, когда выполняются все условия ниже:

- он запускается только с `.env`
- `POST /v1/chat/completions` работает без вручную захваченного request template
- и streaming, и non-streaming ответы стабильны
- tool calls работают по полному циклу request/execute/commit
- истёкшая или невалидная auth обрабатывается предсказуемо
- тесты покрывают критические adapter paths
- документации достаточно, чтобы другой пользователь смог развернуть и использовать gateway без ручного реверс-инжиниринга Trae
